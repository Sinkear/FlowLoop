核心概念

flowloop 的词汇表——goal 是状态权威的唯一持有者；其他都只上报。

#状态权威

Goal

一个工作项。状态权威的唯一持有者——run 只上报，从不决策。

backlogactivereviewdone
$ flowloop create goal --title "重构 intake" --assignee claude
goal g7a3 已创建 → run r9k1 已入队

Run

某个 agent 在 goal 上的一轮。无权威——只向 goal 层上报。

queuedrunningcompletedfailed
$ flowloop goal list
  g7a3  active   重构 intake   [claude]
  g6f2  review   修复飞书流式  [opencode]

Domain

仓库型或 scratch 工作区。验收级别在 goal 上选。

reposcratchhitl/hootl
$ flowloop create domain --name demo --type repo \
    --git_url git@github.com:org/repo

#执行

Runtime

一个启动规格——传输 + provider + 可执行文件/参数 + env。

acpjsonljsonrpcstdio
# transport: stdio | ws | tcp
# provider: acp | jsonl | jsonrpc
opencode acp --pure

Agent

一个 runtime + 人设（system prompt / model / env / MCP server / 并发）。

personamodelmcp
$ flowloop agent create --runtime opencode \
    --system-prompt "你是一个严谨的审查者"

Chat

与 agent 的直接 ACP 对话。daemon 原样转发帧到机器端 CLI。

ACP流式per-agent
GET /agents/{id}/acp  →  WebSocket
# 帧双向原样转发

#协调

Squad

一个不做任何事的路由组——goal 路由到队长，队长通过子目标委派。

leaderdelegatereviewers
$ flowloop squad create --name review-team \
    --leader claude --reviewer opencode

Sub-goal

从 goal 拆出的工作项（无递归）。自己的执行者 + 可选 agent 验证器。

splitverifier≤3 重试
$ flowloop subgoal create --parent g7a3 \
    --title "补测试" --assignee opencode

Change

子目标的逻辑交付物。owner 通过 integrate_change 工具整合。

readyintegratingconflict
$ flowloop change integrate ch9f2
# 冲突 → 执行者返工 → revision N+1

#验证与交付

Verifier

具名 agent 通过 verify_sub_goal 出结构化判定。没有内置域测试执行器：检查写进任务说明，或加 verifier agent。

agentverdictoptional
# verifier agent: verify_sub_goal → pass/fail
# 平台不执行域测试命令

Gates

人工卡点：goal 的 HITL 评审、蓝图的 gate 节点。

hitlblueprint gatehuman
# HITL: goal 停在 review
# 批准 → goal:approved → 合并 + 复验 + 推送

Mention

Consult 原语——评论里的结构化 URI 把 agent 拉进只读 guest run。

consultguestauto-resume
$ flowloop goal comment --text \
    "[@opencode](mention://agent/a4) 这样安全吗?"

Schedule

一个 cron 模板，每次触发克隆一个 goal。幂等、时区感知。

cronidempotenttz-aware
$ flowloop schedule create --goal g7a3 \
    --cron "0 9 * * 1-5"
